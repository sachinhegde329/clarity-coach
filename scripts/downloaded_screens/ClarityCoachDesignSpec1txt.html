Clarity Coach Design Specification Screens, functionality, interaction patterns, and per-session variations. Companion to the PRD and Curriculum Rationale. Structure: foundations, then the screen system specified once, then 36 sessions with only what varies, then cross-cutting concerns. Part 1 � Foundations How to use this document This document specifies how the product is built, not what it teaches (that is the Curriculum Rationale) or why it exists (that is the PRD). It is the reference a developer and designer build from. Read it in three passes. First pass: skim Foundations and the Screen Taxonomy table to grasp the surface area of the product. Second pass: read the Screen System sections in order. Each screen is specified once with all its states, interactions, and edge cases. Third pass: when designing or building a specific session, jump to its entry in Part 3 to find what differs from the system. Wireframes throughout this document are intentionally low-fidelity. They communicate composition, hierarchy, and relative scale. Specific typography, exact spacing, and final colour values are deferred to the design system, which is locked separately. Six design principles Every screen decision in this document derives from these. Where the document is silent, defer to these principles. � 1. Direct, never decorative. Every element earns its existence. No background patterns, no ornamental icons, no animations that do not communicate state change. If removing an element loses meaning, keep it. If it only loses busyness, cut it. � 2. Numbers before words. On any screen showing performance, the user understands how they did within one second of looking. Words exist to interpret data, not to praise the user. � 3. One decision per screen. The product has already decided what the user needs today. Their only choice is whether to start. Anywhere a user faces a menu, ask whether the menu is necessary. � 4. Locked is aspirational, not punitive. Premium content is visible with lock icons, not hidden. The user feels pulled toward locked content, not blocked from it. � 5. Restraint scales; ornament dates. Commit to typography over colour, structure over decoration. The product should look good in 2030. � 6. Pressure-free voice. Microcopy, error messages, empty states all sound like a quiet, capable mentor. Never cheery, never anxious, never urgent. Design tokens (placeholder) Specific values are owned by the design system, not this document. This is the structural reference. Token family Values needed Colour Ink (primary text and buttons), paper (backgrounds), parchment (subtle borders and disabled states), sage (success and improvement), warning red (regressions and errors only), and one accent colour for confirmation moments. Six colours total. Type One sans for body and headers, one mono for numerals. Four sizes: display, body, meta, label. Two weights: regular and medium. No bold; medium does what bold would do. Spacing Multiples of 4: 4, 8, 16, 24, 40, 64. Notably no 32 � forces explicit choice between tight (24) and loose (40). Corner radius 4pt default. 28pt for full-bleed cards (e.g., the Today card). Iconography Line icons at 1.5pt stroke (Tabler, Phosphor Thin, or equivalent). Used sparingly � most affordances are text labels. Part 4 � Cross-cutting concerns Concerns that span all screens. Specified here once, applied throughout. Notifications Push notifications are sparingly used. Three rules: � Daily session reminder. One per day, at the user's chosen practice time. Copy: "Session 14 is ready. Five minutes." No urgency, no manipulation, no streak guilt. If the user has not opened the app for two days, the reminder copy softens: "Welcome back when you're ready." � Skill milestone notifications. Triggered when a metric improves by a meaningful threshold (e.g. fillers down 30 per cent from baseline). Surfaced as a notification: "Your fillers are down 38 per cent. Worth a look." Tappable into the relevant Stats drill-down. � Sprint completion notifications. Triggered immediately on completing a Review session, in case the user backgrounds the app before seeing the celebration state. Copy: "Sprint 3 complete. Sprint 4 begins when you're ready." Explicitly forbidden: streak-loss warnings, engagement-driven reminders unrelated to skill progress, generic re-engagement nudges. The product never manipulates users into returning. Permissions � Microphone. Required. Requested on the Vibe Check onboarding screen � first time the user encounters the mic. If denied, fallback to typed-baseline mode (degraded experience but functional). A persistent banner appears on subsequent sessions inviting the user to grant access. � Notifications. Optional. Requested after the user's first successful session (session 1 complete). Phrasing: "Want a daily nudge?" � never "Allow notifications." Defer system permission dialog until the user opts in. � Speech recognition. iOS and Android each have a speech recognition permission separate from microphone. Requested at the same time as microphone. Accessibility � Voice-over and screen reader. Every screen must be navigable with screen reader. Metric numerals announce as their value plus unit ("4 fillers, down 8 from baseline"). Waveforms have textual alternatives describing the recording's shape. � Audio alternatives. Every tidbit has a transcript. Every audio cue (recording start, recording stop) is paired with a visual cue. The app is fully usable by a profoundly deaf user � they can practice speaking and read the analysis, even if they cannot hear the tidbits. � Visual alternatives. Every visual cue has an audio alternative for users with low vision. The pace indicator beside the mic, for example, has an optional audio tick that increases or decreases in frequency with pace. � Motion. All animations respect the user's reduce-motion preference. Sessions are usable with all animations disabled � only state changes remain. � Touch targets. All interactive elements meet WCAG minimum 44pt touch target.
